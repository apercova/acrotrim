# v1 conformance fixtures

Each `.jsonl` line is a JSON object with a stable case `id`, string `input`, and exact string `expected` result. A case may set `strict: true` to enable the general regex rule, set `lang` to scope literal matching (case-insensitively, including parent tags), or define `expectedError` for invalid input. Fixtures require no entity type, rule configuration, or expected audit metadata.

Implementations MUST produce the expected string for every valid case. Fixture expectations are explicit and must not be generated by invoking an implementation.
